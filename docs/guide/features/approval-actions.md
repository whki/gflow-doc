## 动作总览

办理人在「待我审批」打开单据，高频的**通过 / 拒绝**按钮直达，低频动作收在「更多」下拉里。每个节点开启哪些动作由流程设计器逐节点配置，默认只开通过 / 拒绝：

| 动作 | 谁在用 | 前提 | 操作后 |
|---|---|---|---|
| 通过 / 拒绝 | 办理人 | 固定可用，不可关闭 | 按节点驳回策略流转 |
| 签收 / 取消签收 | 候选人 | 角色/部门候选任务 | 签收后他人不可再办 |
| 转办 | 办理人 | 设计器开启 transfer | 任务彻底移交，自己出局 |
| 委派 | 办理人 | 设计器开启 delegate | 受托人审完自动归还，自己再审 |
| 回退 | 办理人 | 设计器开启 return | 退到上一个已办审批节点重审 |
| 加签 | 办理人 | 设计器开启 addSign | 追加审批人先审，全审完自己再出结果 |
| 减签 | 办理人 | 设计器开启 reduceSign | 移除未办理的加签/会签人 |
| 收回 | 办理人（自己最近一票已通过） | 后续节点无人办理；流程未关闭 recall（缺省开启） | 作废后续待办，流程回到自己重新待审 |
| 撤回 | 发起人 | 实例在途 | 实例终止，可改表单重新发起 |
| 催办 | 发起人/管理员 | 设计器开启 urge | 办理人收提醒，状态不变 |

## 转办与委派的区别

两个动作都是「把单据交给别人」，差别在**最终由谁拍板**：

|  | 转办 | 委派 |
|---|---|---|
| 一句话 | 这单不该我审，换人 | 帮我先把关，最后我拍板 |
| 任务归属 | 彻底移交，原办理人出局 | 受托人审完自动归还原办理人 |
| 最终结果 | 新办理人直接出 | 原办理人参考受托人意见后再审一次 |
| 留痕 | transfer_from / transfer_reason / transfer_time | owner / delegate_from，归还时原办理人收通知 |

委派的完整链路（张伟 → 李娜）：

1. 张伟在待办详情点「更多 → 委派」，选择李娜并说明缘由
2. 单据进入李娜的待办，李娜照常审批
3. 李娜点「通过」后流程**不流转**：任务自动回到张伟名下，张伟收到「委派任务已归还」通知，李娜的审批意见保留在审批时间线里供参考
4. 张伟审阅后再点「通过」，流程才继续向下

> 委派不能指派给自己；被委派人点「拒绝」同样归还，是否驳回由原办理人决定。

## 回退

发现上一环节审得有问题时，用「回退」把单据退回去重审：

- 只能退给**上一个已办审批节点**，不能跨节点挑目标，也不能直接退发起人
- 被退回的单据标记「已退回」，目标节点重新生成待办，表单数据与变量随行带回
- 确实需要退回发起人改材料的，走「拒绝」并给节点配驳回 `reject.strategy: toStarter`

## 加签与减签

**加签**：审批中途需要更多人把关时，把新的审批人插到自己这一环前面（前加签）。被加签人全部审完后才轮到自己出结果；等待期间自己的通过 / 拒绝按钮置灰，并提示尚在等待哪些人。

**减签**：加错了人，或会签里有人长期不办，把**还没办理**的加签人 / 会签人移出去：

- 已出结果的人不能移除
- 会签 / 票签节点减签后按规则重算：剩余票已满足阈值就直接出结果流转
- 全部移除（无人能审）时实例终止，避免流程卡死

## 撤回

申请发出去又后悔了：发起人在「我的申请」里可撤回在途单据。撤回后实例终止（标记「申请人撤回」），在途任务全部作废，修改表单后可重新发起；已完结的流程不能撤回。

## 收回

审批人版的"后悔药"：自己刚通过的票，后续还没人办理时可以收回重审。收回后您通过之后创建的待办全部作废（原办理人收通知），流程回到自己名下重新待审，审批时间线该票显示「已收回」。

**可以收回**：

- 自己最近一票已通过，且后续节点尚无人办理（停在待签收 / 候选任务上也算"未办理"）
- 顺序 / 会签多人的场景，您是该轮最后一位办理人、您之后没有任何人办理过
- 已完结的申请：发起人或管理员可在收回窗口期内整单收回，流程重开末节点重审，审完再次归档（窗口默认 7 天，流程设计器「高级设置 → 审批人设置」可调，1-365 天）

**不能收回**：

- 您通过之后有人已办理（存在更晚的办理记录）
- 您的审批之后流程执行过自动化动作（HTTP 调用、自动化节点等已发生的效果无法安全回退）
- 流程处于挂起状态；已完结申请超过窗口期
- 收回只能收回自己的票；流程设计器里显式关闭了「收回」开关的流程（缺省开启）

## 离岗代审

请假、出差、长假期间不方便审批：在 **个人中心 → 离岗代审** 设置代理规则，启用期间新产生的审批任务自动转给代理人，详情页会注明「代审任务」的来龙去脉，代理人正常通过 / 拒绝，代审意见计入审批记录。

- 代理人须是同租户内启用状态的用户，不能是本人；同一时段只允许一条生效规则，也不允许串联代理（代理人同时段不能自己再设代理）
- 可选「同时把现有待办转交」：规则生效即把名下在途待办一并转给代理人
- 规则结束或到期后新任务回到本人名下，已转出的不回流；「转交存量」可补转
- 员工离职时管理员执行「停用并交接」，系统自动创建长期代审规则并转交在途任务；停用后新任务由其主部门负责人或租户管理员兜底，不会悬空
- 与[转办](#转办与委派的区别)不同：离岗代审按**人 + 时段**自动路由新任务，转办只处理手头这一单
